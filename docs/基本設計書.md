# 基本設計書

## 1. システム構成

```text
利用者のブラウザー
  ├─ index.jsp / WEB-INF配下のJSP
  ├─ Servlet URL（GET画面表示、POST回答登録）
  └─ 模試タイマー（ブラウザーJavaScript）
        │ HTTP
        ▼
Tomcat 11 / Jakarta Servlet
  ├─ controller: リクエスト検証、処理選択、画面遷移
  ├─ dao: JDBCによるMySQLアクセス
  └─ beans: 設問・本文・結果の表示用オブジェクト
        │ JDBC
        ▼
MySQL toeic_learning_system
  ├─ questions / passage_groups / passage_group_items
  ├─ learning_history
  └─ mock_exam_results
```

JSPの画面表示にはJSTL/ELを使用します。DBアクセスはDAOに分離され、Servletから呼び出されます。問題本文は `PassageGroupDao` で取得し、`PassageQuestionGrouper` が設問と本文セットを結び付けます。

## 3. 画面・画面遷移

```text
index.jsp
  ├─ PracticeServlet
  │    ├─ partTypeなし → パート選択
  │    └─ partType=5/6/7 → 練習問題表示
  │          └─ PracticeResultRegistrationServlet (POST)
  │                └─ PracticeResultsServlet?historyId=...
  │
  ├─ MockExamServlet
  │    └─ 100問・75分の模試
  │          └─ MockExamResultRegistrationServlet (POST)
  │                └─ MockExamResultsServlet?mockId=...
  │
  ├─ PracticeResultsServlet → 練習履歴
  └─ MockExamResultsServlet → 模試履歴

練習結果画面 ─ ResultsCsvServlet?type=practice → CSV
模試結果画面 ─ ResultsCsvServlet?type=mock     → CSV
```

JSPは直接公開しないよう、表示用画面を `WEB-INF` 下に配置しています。ホーム `index.jsp` はWebアプリケーション直下です。

## 4. 主要データフロー

### 4.1 練習

1. 利用者がパートを指定して `PracticeServlet` にGETする。
2. `QuestionDao` が当該Partの設問を取得する。誤答優先時は各問題の最大 `history_id` の回答結果を調べる。
3. Part 6/7は本文グループと文書をロードして画面表示用にまとめる。
4. 利用者が1問ずつ回答し、POSTする。
5. Servletが問題ID・パート・A～D回答を検証し、DB上の正答と比較する。
6. `LearningHistoryDao` が新しい回答履歴を追加し、該当結果画面へリダイレクトする。

### 4.2 模試

1. `MockExamServlet` は新規模試で100問を抽出し、問題リストと開始時刻をHTTPセッションへ保存する。
2. Part 6/7は、抽出済み問題の本文グループを読み込んで表示する。
3. ブラウザーのタイマーが期限到達時にフォームを送信する。利用者は期限前に手動提出することもできる。
4. 登録Servletはセッション内の問題セットを使って正誤を数え、結果集計を保存する。
5. セッション内の進行中模試データを除去し、結果画面へリダイレクトする。

## 5. 画面設計方針

- 動的な問題文・本文等はJSTL `<c:out>` で表示する。
- Part 6/7は文書種別、文書番号、発信者を表示し、複数本文の関係を把握できるようにする。
- 模試は問題番号を全体通し番号で表示する。
- 結果詳細と直近100件を同じ画面に表示する。
- 結果画面からCSVダウンロードと学習継続へ移動できる。

## 7. エラー方針

- 不正なパート・ID・回答は400系エラーまたは画面上のエラーメッセージで扱う。
- 該当する結果がない場合は404。
- DAOのSQL例外は `ServletException` としてコンテナへ伝える。
- DB接続失敗や問題不足は成功画面に見せかけずエラーとして扱う。
- 本番向けの利用者に分かりやすい共通エラー画面、ログ・監視方式は未整備。
