# 要件定義書（As-built）

## 1. 目的・適用範囲
このアプリは、TOEIC ReadingSectionをターゲットとしスコアアップのための学習をサポートするものである。練習モード・模試モードを実装し、運用は個人で行うこととし、外部APIやログイン機能、セキュリティ関連の問題は考慮しないこととする。

## 2. 利用者とシステム境界

- 想定利用者: ローカルまたは限定環境で学習する単一利用者（現行実装からの推定）
- Webアプリケーション: Jakarta Servlet/JSP。画面遷移とリクエスト処理をServlet、表示をJSPが担当。
- 永続データ: MySQL。問題、本文グループ、練習履歴、模試結果を保持。
- ブラウザー側処理: 模試残り時間の表示、時間切れ時のフォーム送信。
- 外部サービス連携: 現行機能に認証サービス、スコア連携、外部API連携はない。

### 3.1 練習モードの詳細

- パート選択は5～7。パラメーターがない場合は選択画面を表示する。
- 選択したパートの問題はすべて取得し、最新の誤答を優先した後、問題ID順に並べる。
- 各設問に対して個別に回答を送信する。
- 回答の保存後、該当履歴の詳細と直近100件の履歴を表示する。
- 本文グループのある問題は、グループ内の文書を順序とspeaker付きで表示する。

### 3.2 模試モードの詳細

- 模試対象はReadingのみ。Listeningは含まれない。
- 問題構成はPart 5=30、Part 6=16、Part 7=54、合計100。
- 制限時間は75分。タイマーはブラウザーでカウントダウンし、0になると送信する。
- サーバー側では開始から75分30秒を超えた送信について、全問未回答として集計する。模試結果レコード自体は保存対象となる。
- 公式換算スコアではなく、正答数/100の百分率を表示する。
- DBに保存される模試結果は集計値であり、設問ごとの回答・正誤は保持しない。

## 4. 画面・入出力要件

画面は英語表記のUIを含みます。画面、Servlet URL、遷移は「03_基本設計書」「04_詳細設計書」を参照してください。JSPはJSTL/ELを利用し、問題や本文などの動的テキストは `<c:out>` で出力します。

CSVはUTF-8（BOM付き）で出力します。練習CSVには履歴ID、回答時刻、パート、問題ID、設問、回答、正答、正誤、解説が含まれます。模試CSVには開始・終了時刻、問題数、回答数、正答数、誤答数、未回答数、正答率、経過秒数が含まれます。

## 5. 非機能要件・制約

| 分類 | 現状 |
|---|---|
| 実行環境 | Eclipse Dynamic Web Project。設定上Java 25、Tomcat 11、Web Facet 6.1 |
| DB | MySQLをJDBCで利用。JDBCドライバー8.0.33がプロジェクト内に存在 |
| 表示 | UTF-8、JSTL 3.x、JakartaタグURI `jakarta.tags.core` |
| セキュリティ | ログイン・利用者別アクセス制御なし。DB接続設定は現行ソース内にあるため外部化が必要 |
| 可用性 | 単一のEclipse/Tomcat/MySQL実行環境を前提とし、可用性目標は未定義 |
| 性能 | 負荷要件・同時利用者数・応答時間目標は未定義。模試抽出に `ORDER BY RAND()` を使用 |
| データ保持 | 練習履歴と模試結果の削除・保存期間を管理する機能はない |
| アクセシビリティ | 基準・適合状況は未評価 |

## 6. データ要件

- `questions` に設問、選択肢、正答、解説、Part、本文グループ情報を保持する。
- `passage_groups` と `passage_group_items` に本文セットと文書を保持する。
- `learning_history` は回答ごとの追記履歴とし、回答訂正で既存履歴を上書きしない。
- `mock_exam_results` は模試単位の集計結果を保存する。
- 正確なカラム型、主キー、外部キー、NOT NULL、インデックスは実DB DDL未確認のため「05_DB設計書」で要確認としている。
