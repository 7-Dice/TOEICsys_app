# TOEIC Learning System システム概要・要求分析書

## 1. 提案概要  
このアプリケーションは、ユーザーがTOEICの学習をすることの手助けを主目的としています。同時に、全体的なシステムアーキテクトを行うことで経験値を高めることを副次的な目的としています。

### 2.1 背景

当アプリケーションは、Reading Part 5～7の練習、Reading模試、回答履歴・模試結果の参照とCSV出力が実装する。Eclipse、Servlet/JSP、MySQLを用いた個人学習向けWebアプリケーションとして、既存問題を使った継続学習と実力推移の振り返りを支援します。

### 2.2 提案する運用価値

- 練習モードで各問題の回答と正誤を記録し、直近の回答が誤答である問題を優先して復習する。
- 模試モードでReading形式の問題を時間制限付きで解き、正答数・誤答数・未回答数を振り返る。
- 結果を一覧・CSVで保存し、表計算ソフト等で学習記録を確認できる。
- Part 7の複数文書を、グループ・文書順・発信者の単位で表示する。

### 2.3 提案する次の段階

まずは現行環境でEclipseからの再配備と一連の受入確認を完了し、問題セット単位の模試出題、DB設定の外部化、再現可能なテスト・DB初期化手順を整備します。その後、Gitブランチ運用とリリース手順を導入し、必要に応じて利用者・認証・データ分離を検討します。

## 3. 対象と範囲

### 3.1 現行実装に含まれる範囲

- Reading Part 5、Part 6、Part 7のパート別練習
- 練習回答の採点と `learning_history` への履歴保存
- 最新の回答が誤答の問題を優先する練習問題一覧
- Reading模試（Part 5～7、100問、75分）
- 模試結果の概要保存と一覧表示
- 練習結果・模試結果のCSV出力
- Part 6/7の本文グループ、複数文書の表示

### 3.2 現行実装の対象外

- Listeningセクション（模試・練習とも対象外）
- TOEIC公式の換算スコア・公式採点
- アカウント、ログイン、複数利用者ごとの履歴分離
- 模試中の回答内容や設問別正誤を含む模試レビュー
- 問題・本文を管理する編集者向け画面
- 本番公開に必要な運用監視、バックアップ自動化、可用性保証

## 4. 想定利用者・利用条件

ログイン機能は持たず、DBの回答履歴・模試結果を利用者別に分離しません。したがって、実装上はローカル環境等で単一利用者が使う構成を想定します。複数人が同じDBを使う場合、履歴の混在を防ぐ仕組みが必要です。

## 5. 提案効果と評価指標

| 目的 | 評価方法の例 |
|---|---|
| 誤答の復習 | 最新誤答の問題が練習一覧の先頭側に表示されること |
| 継続学習 | 回答履歴の件数・日付を結果画面またはCSVで確認できること |
| 模試形式の練習 | 100問が表示され、75分経過時に提出されること |
| 学習結果の把握 | 正答・誤答・未回答の合計が総問題数と一致すること |
| データ再利用 | CSVを文字化けせず表計算ソフトで開けること |

これらの指標は提案であり、現時点で正式なサービスレベル目標として合意されたものではありません。

## 6. 前提・リスク

- 問題データと本文データが、アプリケーションが要求する数量・関連付けでDBに登録されていること。
- 現在の抽出処理は模試の設問をランダムに選びます。Part 7では本文セット単位ではなく設問単位で抽出するため、同一本文に属する設問が部分的に選ばれる可能性があります。
- Java/Eclipse/Tomcat/MySQLのバージョン差、JSTLライブラリの配置、DB接続設定が起動に影響します。
- 問題データは公式教材との同一性・正確性を保証しません。権利関係を確認した素材のみ利用してください。
- DB接続設定は現状ソース内に記述されているため、DB接続クラスは.gitignoreファイルとし非追跡とする。

## 7. 導入・改善の推奨順

1. EclipseでClean/Publish/再起動を行い、画面から練習・模試・結果・CSVまで受入確認する。
2. Part 7模試を本文セット単位で抽出し、抽出結果の問題数とパート構成を検証する。
3. DB接続情報を環境変数またはEclipseの外部設定へ移し、公開対象から除外する。
4. DBスキーマ作成・サンプルデータ投入・バックアップの手順を確定する。
5. Gitでfeatureブランチ、レビュー、mainへの統合という小規模なGitflow相当の運用を始める。
6. 複数利用者や外部公開が必要になった時点で、認証・認可・利用者別データ分離を要件化する。
