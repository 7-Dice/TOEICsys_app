# 詳細設計書

## 1. HTTPエンドポイント

| URL | Method | 入力 | 成功時の動作 |
|---|---|---|---|
| `/PracticeServlet` | GET | `partType`（省略可、5～7） | パート選択または練習問題を表示 |
| `/PracticeResultRegistrationServlet` | POST | `questionId`, `partType`, `answer` | 回答を採点・履歴保存し、結果へリダイレクト |
| `/PracticeResultsServlet` | GET | `historyId`（省略可） | 指定履歴の詳細と直近100件を表示 |
| `/MockExamServlet` | GET | なし | セッション上の進行中模試または新規模試を表示 |
| `/MockExamResultRegistrationServlet` | POST | `answer_{questionId}` | セッション問題を採点・集計し、模試結果を保存 |
| `/MockExamResultsServlet` | GET | `mockId`（省略可） | 指定結果の詳細と直近100件を表示 |
| `/ResultsCsvServlet` | GET | `type=practice` または `type=mock` | 対象履歴のCSVをダウンロード |

URLは `@WebServlet` アノテーションで定義されています。`web.xml` はWelcome Fileを定義します。

## 2. 練習処理

### 2.1 問題一覧

- `partType` がない場合はパート選択画面を表示。
- 数値でない場合、または5～7以外の場合はエラーメッセージを表示。
- `QuestionDao.getQuestionsForPractice(partType, true)` を呼び出す。
- 優先対象は `learning_history` 内の問題ごとの最新履歴が `is_correct = FALSE` の設問。
- 誤答優先対象を先にし、各群は `question_id` 昇順にする。
- Part 5は単独設問として表示。Part 6/7は本文グループと設問グループに分ける。

### 2.2 回答登録

1. `questionId` と `partType` を数値として解釈する。失敗時は400。
2. `answer` がA～D（大文字・小文字不問）か確認する。無効値は400。
3. DBから設問を取得し、存在とパート一致を確認する。失敗時は400。
4. サーバー側の正答と比較する。
5. 正誤・回答を `learning_history` に1行追加する。
6. 生成された履歴IDを付けて `PracticeResultsServlet` へリダイレクトする。

回答履歴は追記型です。正答しても過去の誤答履歴は削除されません。最新の履歴が正答なら、誤答優先条件から外れます。

## 3. 模試処理

### 3.1 問題抽出

`QuestionDao.getRandomMockExamQuestions()` はカテゴリ別に `ORDER BY RAND() LIMIT ?` を実行します。

| 対象 | 抽出数 |
|---|---:|
| Part 5 | 30 |
| Part 6 | 16 |
| Part 7 SINGLE | 29 |
| Part 7 DOUBLE | 10 |
| Part 7 TRIPLE | 15 |
| 合計 | 100 |

100問未満または超過の場合はSQL例外扱いです。抽出後はPart、本文グループID、設問順序、問題ID順に並べます。
**Part 6/7の本文セットを単位に選ぶ処理ではなく、設問をランダム抽出する設計です。** そのため、同じ本文セットの全設問が模試に含まれることは保証されません。

### 3.2 模試セッション

- セッション属性 `mockExamQuestions` に問題リストを格納する。
- セッション属性 `mockExamStartTime` に開始時刻を格納する。
- 両方が存在する場合、GETで再アクセスしても同じ問題セットを再表示する。
- 問題IDごとの通し番号を画面表示用に準備する。
- 制限時間は `75 * 60` 秒。

### 3.3 採点・結果登録

- 進行中の問題リストと開始時刻がなければ400。
- セッション問題数が100でなければ400。
- 回答パラメーター名は `answer_{questionId}`。A～D以外または未入力は未回答扱い。
- 経過時間が75分30秒以下の場合、入力値を採点する。これを超えた場合は採点ループを行わず、全問未回答扱いとする。
- `incorrect_count = answered_count - correct_count`。
- `unanswered_count = 100 - answered_count`。
- 保存成功後に模試セッション属性を削除し、`mockId`付き結果画面へリダイレクトする。
- 模試の回答選択や設問別正誤はDBに保存されない。

## 4. 結果一覧とCSV

- 練習結果・模試結果は新しいID順で取得する。
- 画面の一覧は直近100件。詳細対象IDがある場合は同じ画面に詳細を表示する。
- CSV出力は `findAll()` による全件取得。
- UTF-8 BOMを付与し、各値を引用符で囲み、値内の引用符を二重化する。
- CSVセルの先頭が `=`, `+`, `-`, `@` の場合はシングルクォートを付与する。
- 出力件数のページング・期間指定はない。

## 5. 画面データ・主要Bean

| Bean | 主な項目 |
|---|---|
| `Question` | 問題ID、本文グループID、設問順、Part、設問文、選択肢A～D、正答、解説 |
| `PassageGroup` | グループID、Part、グループ種別、タイトル、本文項目一覧 |
| `PassageGroupItem` | 本文ID、グループID、表示順、発信者/文書名、本文 |
| `LearningHistoryRecord` | 履歴ID、問題ID、Part、設問、回答、正答、正誤、回答日時、解説 |
| `MockExamResult` | 模試ID、開始・終了時刻、総数、回答/正答/誤答/未回答数 |

## 6. 例外・入力検証

| ケース | 動作 |
|---|---|
| `partType` が非数値/範囲外 | 練習画面でエラーメッセージ |
| 回答登録のID/Partが不正 | HTTP 400 |
| 回答がA～D以外 | HTTP 400 |
| 問題が存在しない、Partが一致しない | HTTP 400 |
| 結果IDが非数値 | HTTP 400 |
| 結果IDに対応する行がない | HTTP 404 |
| DBアクセス失敗 | ServletExceptionとしてコンテナへ伝播 |
| 模試セッションなし、問題数不正 | HTTP 400 |
| CSV typeが不正 | HTTP 400 |

## 7. 実装上の境界・留意点

- 模試タイマーはJavaScriptによるクライアント処理です。期限切れ時の送信はブラウザー実行に依存します。
- サーバー側の時間判定は75分30秒を超えた場合に無回答として扱うもので、公式な試験監督機能ではありません。
- Mock結果は集計のみで、後から模試問題別の復習はできません。
- `ORDER BY RAND()` はデータ量増加時の性能を確認する必要があります。
- ログイン・CSRF対策・利用者別の認可は実装範囲外です。外部公開時は別途設計・検証してください。
